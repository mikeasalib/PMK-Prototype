## Goal

Overwrite the current project's source with everything in `VA_Program_Command_styled.zip` so the remix matches the styled version, without breaking the remix's Supabase wiring or router.

## What gets replaced

Everything in the archive under these paths gets copied over the current project:

- `src/components/**` (including `ui/`, `AppLayout.tsx`, `DataSourcesFooter.tsx`, `RefreshButton.tsx`, `va-ui.tsx`)
- `src/hooks/**`
- `src/lib/**` (including `sync.functions.ts`, `sync.server.ts`, `va-data.ts`, `va-glossary.ts`, `workstream-updates.ts`, etc.)
- `src/routes/**` (all page routes + `__root.tsx` + `README.md`)
- `src/router.tsx`, `src/server.ts`, `src/start.ts`, `src/styles.css`
- `public/favicon.ico`
- Top-level configs: `AGENTS.md`, `bun.lock`, `bunfig.toml`, `components.json`, `eslint.config.js`, `package.json`, `tsconfig.json`, `vite.config.ts`, `.prettierrc`, `.prettierignore`, `.gitignore`

## What is intentionally NOT overwritten

These are tied to the remixed project's own backend/tooling and must stay as-is:

- `.env` — the zip points at the source project's Supabase (`mqhvln…`); this remix uses `tfbcm…`.
- `src/integrations/supabase/client.ts`, `client.server.ts`, `types.ts`, `auth-attacher.ts`, `auth-middleware.ts` — Lovable-managed, regenerated per project.
- `supabase/config.toml` — auto-managed.
- `supabase/migrations/**` — already identical in both, no action needed.
- `src/routeTree.gen.ts` — regenerated by the TanStack Router Vite plugin at dev/build time; if the zip's copy differs it will be re-emitted.
- `.lovable/project.json` — remix-specific metadata.

## Safety checks before copying

- Archive contains no `.git` directory (verified).
- Zip's `supabase/migrations/*.sql` filenames match what's already in the project, so no schema drift.
- Connector env vars (`GRANOLA_API_KEY`, `LINEAR_API_KEY`, `NOTION_API_KEY`, `LOVABLE_API_KEY`) were linked earlier and are unaffected by a file-only overwrite.

## Steps

1. `rsync` from `/tmp/user-uploads/…` (extracted copy) into the project root, excluding the "not overwritten" paths above and any `.git` metadata.
2. Run `bun install` to reconcile `package.json` / `bun.lock`.
3. Let Vite regenerate `src/routeTree.gen.ts` on next dev restart.
4. Sanity check: open `/` in preview, confirm the sidebar/footer render and the Refresh button still calls the sync server fns successfully (connectors are already linked).

## Notes

- If any file in the zip references the old Supabase URL/keys directly (rather than via `@/integrations/supabase/client`), we'll patch it to use the shared client after the copy.
- No database changes are needed — the two migration files already exist in this project.
